# Contributing

Start with an issue that defines the decision or behaviour being improved, its acceptance criteria and a small validation plan. Keep changes focused: this is a batch analysis tool, with no service or database to operate.

Use Python 3.12 and install `requirements.lock.txt` in a virtual environment. Run `python -m pytest -q` and `python scripts/verify_snapshot.py` before proposing a change. Tests use synthetic fixtures and committed aggregate outputs; they do not download national source files. CI runs the same checks on Linux and Windows.

Add regression tests for changed behaviour, especially geography, missing values, selection thresholds and source validation. Explain the product effect and validation evidence in the pull request. Methodology changes should describe their effect on coverage and the shortlist.

The files under `output/` are a dated reference delivery. Use a separate `--output-dir` for experiments. The original manifest is not regenerated by stage commands. A new reference delivery needs its own source hashes, parameters, validation and reviewed counts.

Keep raw sources, credentials, local session logs and personal information out of commits and issues. AI assistance is welcome; contributors remain responsible for checking the change. Summarise relevant decisions and tests rather than uploading complete conversations.
